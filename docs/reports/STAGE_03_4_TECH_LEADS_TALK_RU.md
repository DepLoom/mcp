## Слайд 1. Заголовок

Речь:

## Слайд 2. Что и как проверяли
- Реальный корпоративный фронтенд на React 18 (workspaces + lerna + webpack + jest).
- Одна база, две ветки: `agent-only` (без DepLoom) и `deploom` (скилл + MCP, реальное ядро планирования).
- Идентичная задача: обновить РОВНО три зависимости (patch), 58 — строгие исключения.
- Одинаковый бюджет: 1500 с на пилот, одна модель, один промпт.
- После пилотов — независимая контрольная верификация.

Речь:
«Ключевое — честный A/B: одно отличие, только наличие DepLoom. Никакой передачи
решений между ветками, исходный репозиторий не трогали. Контролируем, что
диff соответствует плану, ничего лишнего не задето, сборка и тесты зелёные.»

## Слайд 3. Результаты в цифрах
| | deploom | agent-only |
|---|---|---|
| Время пилота | 1179 с, завершён | 1500 с, TIMEOUT |
| Правки | 3 пакета, точно по задаче | 3 пакета, точно по задаче |
| Верификация агентом | да, вся | не доведена |
| Evidence JSON | да | нет |
| Контрольная верификация | все PASSED | все PASSED |

Речь:
«Оба варианта внесли один и тот же минимальный diff — по сути верный. Но
вариант со скиллом прошёл весь конвейер за один прогон: спланировал, изолировал
работу, установил, проверил typecheck/lint/сборку/тесты, оставил структурированный
evidence. Голый агент упёрся в большую установку зависимостей и сам верификацию
не довёл — результат тот же, но подтверждён уже нашей контрольной проверкой,
а не им.»

## Слайд 4. Где ценность подтверждается
- **Изоляция исполнения** — работа в отдельном worktree, исходный код не трогается.
- **Соблюдение исключений** — ни одной из 58 исключённых зависимостей не задето, мажорных бампов нет.
- **Доказуемая верификация** — evidence JSON со статусами каждой проверки.
- **Честный деградационный путь** — при сбое метаданных реестра скилл не выдумывает цели: помечает `needsReview` и запрашивает подтверждение.

Речь:
«Три «за»: (1) скилл не даёт агенту размазывать работу по всему проекту — он
изолирует и контролирует; (2) исключения держатся железно — это критично для
прод-проектов; (3) результат доказуем, а не «на словах». Отдельно подчёркиваю:
когда провайдер метаданных реестра отвалился, скилл НЕ сочинил версии».

## Слайд 5. Что недотянуто
- Планировщик внутри пилота не смог подтвердить цели из-за сбоя метаданных реестра (registry-failed) → `needsReview=true`, требуется подтверждение пользователя.
- Цель планировщика («последняя в мажоре» по снапшоту) младше фактически доступной версии; исполнитель использует живой `npm view`.
- Синтетические/негативные сценарии в этом окне не перезапускались (NOT_RUN).

Речь:
«Один честный тип «слабостей»: сбой провайдера метаданных уронил планировщик
в плановый деградационный режим — это устойчиво, но критерий «планировщик сам
подтвердил цели» в этом окне не выполнен. Плюс расхождение снапшота метаданных
и живого реестра — не блокер, но требует синхронизации. Негативные сценарии
планируем отдельным прогоном.»
